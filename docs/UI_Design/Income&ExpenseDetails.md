# 📱 页面 3：收支明细页 (Income & Expense Details)

普通记账软件关注 **“流水” (Flow)，而财富管理应该关注“结构” (Structure)**。

对于高净值或有规划的用户，他们的核心关注点不应该是每天喝了几杯咖啡，而是：

- 我的基本盘稳不稳？（周期性固定收支是否健康，如工资 vs 房贷）。
- 本月有哪些意外项？（一次性大额收支对现金流的冲击，如年终奖或突发医疗费）。

基于这个核心思路，我们要彻底重构“收支明细页”，将其升级为 “现金流结构分析页”。

### 🔍 核心交互与设计意图

#### 1. 结构化对比图 (Structured Chart) - 最核心的改动

- 抛弃时间轴折线图：不再关注哪天花了钱。
- 采用堆叠柱状图 (Stacked Bar Chart)：
  - 左柱是收入，右柱是支出。
  - 每根柱子分为两截：底部是“固定/周期性” (基石，用深色)，顶部是“一次性/变动” (浮动，用亮色)。
- 价值：用户一眼就能看出：“我这个月支出高，是因为房贷（固定）太高，还是因为乱买东西（一次性）太多？”

#### 2. 结构详情 Tab与列表

- 不再列出每日流水：默认折叠琐碎信息。
- 固定项 (Recurring)：列出的是你维护的“CashFlowItem”规则。点击跳转到规则编辑页面，而不是某一条流水。体现“管理”视角。
- 一次性项 (One-time)：
  - 对于大额、单笔的一次性记录（如修车），直接展示。
  - 对于小额、多笔的记录（如每天的吃饭打车），进行分类聚合展示（如“购物消费 本月累计 8 笔”）。点击后才进入传统的流水列表页查看明细。

#### 3. 交互流程变化

- 看宏观：在当前页面，通过图表和结构列表看大局。
- 管固定：点击“固定支出”里的卡片，去调整周期性计划。
- 查细账：点击“一次性变动”里的聚合卡片，才进入二级页面查具体的流水。

## 🔍 关键交互细节

- 收支类型切换：
  - 收入：金额文字和保存按钮为绿色。
  - 支出：金额文字和保存按钮为红色。
- 键盘自动弹出：弹窗打开时，焦点应自动定位到“金额”输入框，并弹出数字键盘，减少用户一次点击。
- 突出“周期性”与“一次性”：
  - 不再把“周期性”藏在折叠菜单里，而是把它提权到核心区域，使用一个明显的 **“模式切换器”**。
  - 此笔记录是:                                           |
    [  🔄 周期性固定收支  ]    [  ⚡ 仅一次性记录  ]          | <- 默认选中左侧"周期性"
    (如工资,房贷,水电费)        (如奖金,聚餐,购物)            |
- 周期设置逻辑：
  - 只有当“周期性”模式选中时，才显示“频率”和“日期”选择器。
  - 频率默认为“每月”，日期默认为“今天”。
- 关联资产过滤：点击“选择关联资产”时，弹出的列表中应根据当前的收支类型进行过滤。
  - 如果是“支出”，优先显示负债类资产（如房贷）。
  - 如果是“收入”，优先显示投资/房产类资产（如房租）。
- 保存按钮：
  - 初始状态为禁用，直到用户输入金额和选择分类。
  - 点击保存后，弹窗关闭，返回收支详情页。

- 💡 交互逻辑变化默认模式：弹窗打开时，默认选中 [ 🔄 周期性固定收支 ]。这是为了引导用户建立长期视图。
  - UI联动：选中“周期性”：显示 [4. 周期设置] 区域，隐藏日期选择器（因为由频率和日决定）。
  - 选中“仅一次”：隐藏 [4. 周期设置] 区域，显示一个标准的“日期”选择器（默认为今天）。

- **频率选项 (Frequencies)**
  - 频率选择器应该是一个简单清晰的下拉菜单或底部弹窗。
  - 每月 (Monthly) - 默认 (如工资、房贷)
  - 每周 (Weekly) (如固定家政费)
  - 每季度 (Quarterly) (如某些物业费、会员费)
  - 每年 (Yearly) (如保费、车险、暖气费)

- **日期选择器 (Date Picker)**
  - 日期选择器应该是一个简单清晰的下拉菜单或底部弹窗。
