# AI 对话行为优化需求

## 1. 问题背景

### 1.1 案例分析

**用户输入**：
> 已婚，有1个孩子，每月固定收入3万，房贷5000，车贷2000，固定支出1.2万

**AI 回复**（问题行为）：
> 好的，老友。我们来一起梳理一下你的情况，并基于北京的购房政策，看看你下一步能做什么...
> 
> ### 第一步：分析你的购房资格（基于北京限购政策）
> 1. 京籍家庭：限购2套住房。
> 2. 非京籍家庭：需连续60个月（5年）社保或纳税，限购1套...
> 
> **关于通州区的特殊规定...**

**问题**：用户仅提供了家庭财务信息，**没有询问购房政策**，但 AI 主动输出了大量北京购房限购政策内容。

### 1.2 根本原因

| 层级 | 问题 | 说明 |
|------|------|------|
| Intent | 意图识别缺失 | 未区分"信息收集"与"政策咨询"意图 |
| RAG | 过度检索 | 基于关键词（北京、房产）触发知识检索，无意图过滤 |
| Prompt | 缺少约束 | 系统 Prompt 未限制何时使用检索知识 |
| Response | 信息过载 | 回复内容远超用户当前需求 |

## 2. 最佳实践对比

### 2.1 当前实现 vs 最佳实践

| 维度 | 当前实现 | 最佳实践 |
|------|----------|----------|
| **意图识别** | 无分类，直接处理 | 先分类意图，再决定处理策略 |
| **知识检索** | 基于关键词匹配自动触发 | 仅在"政策咨询"意图时触发 |
| **回复策略** | 有知识就输出 | 仅输出用户明确需要的信息 |
| **对话引导** | 被动响应 | 主动确认用户需求后再深入 |

### 2.2 意图分类框架

```
用户消息 → 意图分类器 → 处理策略

意图类型:
├── INFO_COLLECTION     # 信息收集（用户提供资产/收入等）
├── ASSET_VALUATION     # 资产估值请求
├── POLICY_INQUIRY      # 政策咨询（购房资格、限购等）
├── ADVICE_REQUEST      # 配置建议请求
├── CONFIRMATION        # 确认/修正信息
└── GENERAL_CHAT        # 闲聊/其他
```

## 3. 优化需求

### 3.1 意图识别层

**需求 R1**：新增意图分类器

- 在处理用户消息前，先进行意图分类
- 分类结果决定后续处理策略
- 分类可基于 LLM 或规则引擎

**验收标准**：
- [ ] 用户提供家庭/收入信息时，识别为 `INFO_COLLECTION`
- [ ] 用户询问"我能买房吗？""限购政策"时，识别为 `POLICY_INQUIRY`

### 3.2 RAG 检索层

**需求 R2**：条件触发知识检索

- 仅在意图为 `POLICY_INQUIRY` 或用户明确询问政策时触发 RAG
- 其他意图下禁用外部知识检索

**验收标准**：
- [ ] `INFO_COLLECTION` 意图不触发 RAG
- [ ] `POLICY_INQUIRY` 意图正常触发 RAG

### 3.3 回复生成层

**需求 R3**：回复内容约束

修改 `agent_system.yaml`，添加约束：

```yaml
# 新增回复约束
response_constraints: |
  **信息收集场景**：
  - 仅确认收到信息 + 简要分析 + 询问下一步
  - 禁止主动输出用户未询问的政策/建议
  
  **政策咨询场景**：
  - 先确认用户具体问题
  - 再输出相关政策信息
```

**验收标准**：
- [ ] 用户提供收入信息时，AI 仅确认收到并询问下一步
- [ ] 用户明确询问购房资格时，AI 才输出限购政策

### 3.4 对话引导层

**需求 R4**：主动确认机制

当检测到可能需要政策信息时，先询问用户：

```
✅ 正确示例：
"好的，您的月收入3万，月供共7000，月结余约1.1万。💡 
您是想了解购房资格，还是我们继续完善您的资产信息？"

❌ 错误示例：
"好的，让我帮您分析北京的购房政策..."
```

## 4. 实现建议

### 4.1 Phase 1：快速修复（Prompt 层）

修改 `agent_system.yaml`，添加明确约束：

```yaml
# L7: 回复边界控制
response_boundaries: |
  **严格遵循用户意图**：
  - 用户提供信息 → 确认 + 简析 + 追问
  - 用户咨询政策 → 先确认问题 → 再输出政策
  - 禁止"主动展示知识"行为
  
  **政策信息触发条件**：
  仅在用户明确使用以下关键词时输出政策：
  - "能买房吗"/"购房资格"/"限购"
  - "首付比例"/"贷款政策"
  - 明确询问政策细节
```

### 4.2 Phase 2：架构优化

1. **意图分类服务**：`IntentClassifier`
2. **条件 RAG 触发**：基于意图决定是否检索
3. **回复模板分离**：不同意图使用不同回复策略
