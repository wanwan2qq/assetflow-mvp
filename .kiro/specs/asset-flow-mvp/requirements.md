# 需求文档

## 项目介绍

AssetFlow 是一款 AI 原生的家庭资产配置顾问应用，为中国家庭提供"买方投顾"服务。系统通过 AI 搜索进行房产估值，引导用户完成资产访谈，基于标准普尔四象限模型提供可执行的配置建议。该应用旨在解决中国家庭房产占比过高、缺乏中立理财建议的痛点。

## 术语表

- **资产流系统**: 完整的 AI 原生资产配置应用程序
- **聊天代理**: 基于 LangChain 的对话式 AI 组件
- **搜索工具**: 用于房产定价的 Tavily 搜索 API 集成
- **资产数据库**: 基于 SQLModel 的用户资产信息存储
- **配置引擎**: 标准普尔四象限计算服务
- **Flutter客户端**: 移动应用前端
- **行动卡片**: 结构化推荐 UI 组件
- **估值卡片**: 房产估价确认 UI 组件
- **房产占比**: 房产在总净资产中的百分比
- **流动性比率**: 现金储备相对于月支出的比例

## 需求

### 需求 1: 通过 AI 搜索进行房产估值

**用户故事:** 作为用户，我希望通过自然语言输入获得房产估值，以便在不进行复杂手动流程的情况下建立资产基线。

#### 验收标准

1. 当用户提及房产位置和详细信息时，聊天代理应当提取城市、小区和面积信息
2. 当房产信息被提取时，搜索工具应当使用结构化搜索词查询实时市场价格
3. 当获得搜索结果时，资产流系统应当对挂牌价格应用 0.95 倍数作为保守估算
4. 当计算出估值时，资产流系统应当通过估值卡片界面呈现估值
5. 当用户确认或修改估值时，资产数据库应当存储确认的房产价值

### 需求 2: 对话式资产访谈

**用户故事:** 作为用户，我希望在自然对话中被引导完成资产披露，以便在不感到被审问的情况下完成财务档案。

#### 验收标准

1. 当房产被确认时，聊天代理应当启动关于其他资产类别的引导式询问
2. 当询问资产时，聊天代理应当依次询问现金、投资、负债和保险
3. 当用户用自然语言提供资产信息时，资产流系统应当自动提取数值
4. 当资产价值被提取时，资产数据库应当存储每项资产并进行适当分类
5. 当所有主要资产类别都被覆盖时，聊天代理应当进入分析阶段

### 需求 3: 资产配置健康度计算

**用户故事:** 作为系统管理员，我希望系统计算投资组合健康度指标，以便用户获得准确的财务评估。

#### 验收标准

1. 当用户资产被存储时，配置引擎应当计算总净资产为（房产 + 现金 + 投资 - 负债）
2. 当净资产被计算时，配置引擎应当计算房产占比为（房产价值 / 总净资产）
3. 当现金资产可用时，配置引擎应当计算流动性比率为（现金 / 6个月支出）
4. 当比率超过风险阈值时，配置引擎应当标记适当的警告
5. 当计算完成时，资产流系统应当生成结构化健康评估

### 需求 4: 风险评估和警告

**用户故事:** 作为用户，我希望收到关于投资组合风险的清晰警告，以便了解我的财务脆弱性。

#### 验收标准

1. 当房产占比超过 75% 时，资产流系统应当生成高集中度风险警告
2. 当流动性比率低于 3 时，资产流系统应当生成流动性危机警告
3. 当存在负债但没有保险覆盖时，资产流系统应当生成保障缺口警告
4. 当生成警告时，资产流系统应当通过适当的行动卡片界面呈现警告
5. 当存在多个风险时，资产流系统应当按严重程度优先排序警告

### 需求 5: 结构化响应生成

**用户故事:** 作为开发者，我希望 AI 生成带有嵌入式 UI 组件的结构化响应，以便前端能够动态渲染适当的界面。

#### 验收标准

1. 当房产估值准备就绪时，聊天代理应当在响应中包含 `<WIDGET:VALUATION_CARD>` 标签
2. 当生成推荐时，聊天代理应当包含带有适当类型参数的 `<WIDGET:ACTION_CARD>` 标签
3. 当投资组合分析完成时，聊天代理应当包含用于可视化的 `<WIDGET:PORTFOLIO_CHART>` 标签
4. 当存在结构化标签时，Flutter客户端应当解析并渲染相应的 UI 组件
5. 当流式响应包含标签时，Flutter客户端应当处理实时组件插入

### 需求 6: 商业化推荐配置系统

**用户故事:** 作为用户，我希望收到可执行的推荐并直接访问解决方案，以便高效地解决已识别的财务缺口。

#### 验收标准

1. 当识别出投资组合缺口时，资产流系统应当从商业项目数据库中检索匹配标签（如 "insurance", "broker"）的推荐内容
2. 当推荐专家服务时，行动卡片应当包含联系信息和服务评级
3. 当建议金融产品时，资产流系统应当优先展示后台配置权重（Priority）最高的项目
4. 当用户与行动卡片交互时，资产流系统应当促进与外部服务的连接
5. 当显示推荐时，资产流系统应当跟踪用户参与度以进行优化

### 需求 7: 实时聊天界面

**用户故事:** 作为用户，我希望通过响应式聊天界面与 AI 交互，以便就我的财务进行自然对话。

#### 验收标准

1. 当用户发送消息时，Flutter客户端应当支持文本和语音输入
2. 当 AI 响应时，Flutter客户端应当显示带有打字机效果的流式响应
3. 当响应包含 markdown 时，Flutter客户端应当适当渲染格式化文本
4. 当收到生成式 UI 标签时，Flutter客户端应当内联渲染嵌入式组件
5. 当聊天历史积累时，Flutter客户端应当维护对话上下文和滚动

### 需求 8: 资产仪表板可视化

**用户故事:** 作为用户，我希望以可视化格式查看我的完整资产配置，以便一目了然地了解我的财务分布。

#### 验收标准

1. 当用户访问仪表板时，Flutter客户端应当从资产数据库获取当前资产数据
2. 当检索到资产数据时，Flutter客户端应当渲染显示资产类别分布的饼图
3. 当显示图表时，资产流系统应当显示每个类别的百分比和绝对值
4. 当数据变化时，Flutter客户端应当实时更新可视化
5. 当用户与图表段交互时，资产流系统应当显示详细分解

### 需求 9: 数据持久化和状态管理

**用户故事:** 作为系统架构师，我希望可靠的数据存储和状态管理，以便用户信息在会话间得到保存和访问。

#### 验收标准

1. 当资产信息被确认时，资产数据库应当持久化数据并进行适当的用户关联
2. 当用户返回应用程序时，资产流系统应当恢复之前的资产状态
3. 当数据被修改时，资产数据库应当更新记录同时维护审计跟踪
4. 当存在多种资产类型时，资产数据库应当维护适当的分类和关系
5. 当系统状态变化时，Flutter客户端应当与后端数据同步本地状态

### 需求 10: 搜索集成和数据处理

**用户故事:** 作为开发者，我希望强大的房产定价搜索集成，以便房产估值准确且及时。

#### 验收标准

1. 当启动房产搜索时，搜索工具应当使用城市、小区和当前月份参数构造查询
2. 当返回搜索结果时，资产流系统应当从结果摘要中提取价格信息
3. 当处理价格数据时，资产流系统应当应用保守估算因子
4. 当搜索失败或无结果时，资产流系统应当优雅处理错误并请求手动输入
5. 当搜索数据过时时，资产流系统应当向用户指示数据新鲜度

### 需求 11: 身份验证与数据安全

**用户故事:** 作为用户，我希望我的资产数据被安全加密存储，并且只有我本人可以访问，以保护我的财务隐私。

#### 验收标准

1. 当访问 API 端点时，资产流系统应当验证 HTTP Header 中的 JWT Token（登录/注册接口除外）
2. 当查询资产数据库时，资产流系统应当强制过滤 user_id == current_user.id，严禁跨用户查询
3. 当传输敏感数据时，资产流系统应当使用 HTTPS 加密用户手机号和实际资产数值
4. 当用户使用设备 ID 登录时，资产流系统应当支持匿名模式，并在用户卸载前提示绑定手机号以防数据丢失
5. 当处理用户数据时，资产流系统应当遵循数据最小化原则，仅收集必要信息

### 需求 12: 用户画像与风险偏好

**用户故事:** 作为系统，我需要了解用户的年龄阶段和风险承受能力，以便调整标准配置模型的参数。

#### 验收标准

1. 当开始资产访谈时，聊天代理应当通过自然语言获取用户的年龄段和家庭结构信息
2. 当获得用户画像时，配置引擎应当根据用户画像动态调整风险阈值
3. 当存储用户数据时，资产流系统应当将用户画像数据与资产数据关联存储
4. 当计算配置建议时，资产流系统应当考虑年龄相关的风险承受能力差异
5. 当用户画像不完整时，资产流系统应当使用保守的默认参数进行计算

## 非功能性需求

### 性能要求

1. AI 文本回复的首字延迟（TTFT）应当小于 1.5 秒
2. 房产搜索估值过程的总耗时应当小于 5 秒（可使用加载动画过渡）
3. 资产流系统应当支持至少 100 个并发 WebSocket/SSE 连接

### 容错性要求

1. 当 Tavily 搜索 API 超时或失败时，资产流系统应当优雅降级，提示用户手动输入估值
2. 当网络连接不稳定时，Flutter客户端应当支持离线模式和数据同步
3. 当系统出现错误时，资产流系统应当记录详细日志并提供用户友好的错误信息

### 合规性要求

1. 界面底部必须显示"AI 建议仅供参考，不构成投资承诺"的免责声明
2. 资产流系统应当遵循相关金融数据保护法规
3. 用户数据的收集和使用应当符合隐私保护要求
